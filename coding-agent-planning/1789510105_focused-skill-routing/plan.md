## Why this change is needed

The Payments system session returned the complete current 18,616-byte entrypoint 59 times, including ten repeat reads within the same recorded compaction segment. Other reloads followed actual context loss or host-required reading, so eliminating every reread is neither possible nor the acceptance criterion. The session also treated ordinary payment reviews and publication as moldea workflows and attempted the gate at an invented global path three times despite knowing the repository installation. Its manifest declared no relationships, and the relevant README changes were outside the managed block.

The current entrypoint combines routing with detailed initialization, reconciliation, runtime, pagination, and reporting procedures. Conformance assertions often require those procedures to remain in SKILL.md. The current local-tooling reference mixes observation with installation and prescribes removal or disabling of package-manager hooks as the prerequisite to continue. The Socket warning identifies that operational instruction surface; it does not establish a malicious payload. Containment and package metadata checks do not authenticate executable contents or provide an OS sandbox.

## Final behavior

1. SKILL.md retains concise purpose, instruction reuse, selected-installation identity, relevance routing, essential authority boundaries, bounded launcher syntax, and links to operation owners. Target at most 8,192 UTF-8 bytes, a maintainer regression guard that reduces the current entry cost by more than half, not a user or repository capacity limit.
2. Informational and independent Agent Skill requests retain their existing exceptions. Initialization remains explicit. Explicit repair may diagnose damaged prior adoption but never silently initialize it.
3. After adoption, genuine AI-agent planning, creation, runtime integration, maintenance, review, and contextual continuations remain direct operations. No moldea terminology, bindings, agent count, or literal continuation phrase is required.
4. Coding on the moldea product, a repository name, generic runtime or agent terminology, and host review/fix/push commands do not establish direct intent. Ordinary paths use the full relationship gate, not adoption-only. A README path is insufficient without an intersecting managed hunk. A miss ends moldea handling silently for that request, while host work continues.
5. Retain the exact installed SKILL.md location supplied by the host and resolve sibling resources from it. Do not invent a home-directory installation or rediscover an available path. Missing resources are not permission to execute another copy.
6. Complete unchanged instructions may be reused while available and allowed by the host. After compaction, reload only required missing instructions. Relevance, repository facts, trust, and authorization are separately reassessed. No persistent cache, fingerprints, or read-tracking probes are added.
7. Read-only tooling guidance contains no installation procedure. A dedicated installation reference owns the existing bounded preflight and authorized dependency setup. Executable extensions stop automatic setup; report the exact mechanism, unavailable tooling, stopped operation, and repository-approved trusted setup prerequisite. Never prescribe removing or disabling controls merely to proceed.
8. Gate execution remains limited to shipped skill code. CLI execution remains subject to existing host trust and execution controls, without new mandatory approval prompts. Paths, versions, metadata, and byte limits are not sandbox or authenticity guarantees.
