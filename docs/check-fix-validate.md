# Check, fix, and validate project context

## Check alignment

Ask **Check the support agent's instruction wiring** for a read-only comparison of the canonical instruction and the actual model call. Check gives each assessed owner a structure verdict and reconciles its starting declaration count with the kept, proposed removal and unchecked counts. It gives the roles for paths kept and names the exact paths and evidence for proposed additions and removals and for unchecked declarations. It reports misplaced facts, missing routes and gaps in the evidence. A valid format may coexist with a semantic mismatch. A whole-project Check requires an explicit request.

## Fix a project

Ask **Fix moldea** routinely and after large changes, or name one area to repair. For each assessed owner, the coding agent reports whether its responsibilities are cohesive or mixed. Kept paths appear as counts with their roles. Removed and unchecked declarations are named by exact path with their reasons or evidence gaps. Those three counts must add up to the declarations in the owner's manifest at the start of its assessment. The report lists each exact added path and its evidence separately. Paths with a shared outcome and reason can appear together.

Fix adds missing paths only when the owner's canonical text already references them as paths, links, or named modules or directories. It uses one coherent subtree glob for a collection of directly governed authored deliverables. A path stays or is added only when the agent can name the owner's stated fact or rule and establish the path's role in it. For presentation, build, CI, deployment, asset and content-production paths in those roles, the path must be the sole enforcement point of the named rule. A declaration with no qualifying owner statement is removed with that reason.

The agent proposes the exact split and routes when responsibilities are mixed. If a human doc is the only authority for a durable rule, the agent proposes moving the rule into its canonical owner and replacing the doc's statement with an owner link. After approval, Maintain applies the move within the authorized scope, reports any remaining duplicate and updates the affected routes and relationships. If two sources disagree about intended policy, the agent needs your choice or independent governing evidence.

A whole-project Fix begins with the bundled Git checkpoint helper. It inspects safe bounded Git evidence and never writes Git state. A helper limit, including an attribute filter or unavailable commit, can leave Git-dependent verification incomplete. The report names scope and changes, then gives Checked, Fixed, Verified, Needs input, Not checked, and numbered Next options. A pause or stop records the full commit, next owner, unfinished owners and paths, uncommitted paths and manifest owner entries in the Resume point. Continue in the same conversation. Reassessment uses the current manifest's totals, keeps earlier removals in Changes so far, and revisits unchecked paths even when they have not changed. Fix is complete when every owner has a current verdict, reconciled counts, completed checks of referenced candidates, zero unchecked declarations and the required verification.

Fix can correct an established factual error in a document in the same repository when implementation or the governing owner supplies the evidence. It preserves the document's voice and structure, updates generated documents through their source, and records the evidence for each outside edit under Fixed. Findings in other repositories are reported for their owners.

An existing foundation can be repaired when prior adoption and the intended correction are established. Healthy state is left intact. The managed AGENTS.md block and governing Claude import follow host authority, with an exact handoff for protected files.

## Validate structure

Ask **Validate the moldea project** to run the bundled CLI read-only. Node.js runs the skill while the project can use any language. Validation checks declared files across languages and supported JavaScript and TypeScript ESM symbols. Unsupported symbols remain `not-checked`. The result reports structural errors, warnings, integration and checked bindings. A native connection test provides separate evidence for actual instruction or schema consumption.

A standalone Validate does not take a Fix checkpoint. A completed valid or invalid result establishes invocation. When adoption or execution blocks the check, the agent reports the bounded foundation evidence and the unverified check.

## Resolve a warning

You can authorize a correction or accept an eligible diagnostic with your reason. Integration warnings are eligible only for shared, Git-tracked AGENTS.md or CLAUDE.md instruction subjects. A local-only or ignored file gets a fix or exact handoff. Acceptance stores the reported code, subject and qualifier, and leaves errors and unchecked connections unchanged. Validate after adding or removing an acceptance.
