# Reference-reading checks

The installed `SKILL.md` routes work to six focused references. Conformance checks keep the entrypoint within 8,192 UTF-8 bytes. Host instructions govern mandatory reads. Reuse complete unchanged instructions and retrieve missing instructions after compaction. Instruction reuse establishes no new repository facts or permission to write.

## Routing and instruction reuse

- **Direct work** uses the host-selected installation and reuses adoption evidence or the adoption-only gate before canonical access. This includes project-grounded skills and changes to in-app model behavior.
- **Product planning** uses Use to read `moldea/project.md` and select focused owners. When its routing is missing or unusable, inspect one content-free inventory and open only the passages that can affect the plan.
- **Ordinary work** checks only known paths and scopes a matching batch once before opening canonical owners. Check discovered task paths as a separate known batch. Reuse unchanged scope and keep unrelated work silent.
- **Skill loading** alone supplies no moldea trigger. Check independently targeted inputs, outputs, and implementation paths through their normal routes.

Batch independent known-path reads and reuse shared evidence within the applicable output limits. Continue dependent CLI pages only with the returned cursor and unchanged selection. When assessing a binding, name the owner, file and export when present, what the change establishes, and why the canonical entry stays accurate.

## Behavioral regression checklist

Run native checks in a disposable checkout with the selected skill and bundled CLI. Use a fresh conversation for each initial routing probe. Record the actual gate input and result, the selected entrypoint and reference reads or evidence of complete unchanged reuse, the selected owner, the response, and observed changes. After compaction, check that missing instructions are recovered before work continues. A retrieved reference proves availability. Whether the agent followed it must be established from its actions.

## Repair and validation evidence

For a Fix, recorded Git evidence permits only read-only `git status`, `diff`, `log`, `rev-parse`, and `show` for orientation. Verify the installed helper's checkpoint, comparison on continuation, commit verification, and review of the repair's writes as applicable. The evaluator uses complete wrapper capture and recognized command text. Direct host calls provide no actor credit. Opaque text can pass with clean complete capture. Standalone Validate permits no repair helper call or helper result.

On continuation, inspect the actual checkpoint comparison and owner retrieval. Retain an unchanged assessment only when the checkpoint supports it. If the commit or completed-owner evidence is unavailable, check conservative reassessment or an honest report of what remains unchecked. Observe a bounded stop and the reported checkpoint independently of structural validity.

Use native traces for exact command ordering, Git-tracked status, and which connection test ran. A recorded aggregate test result cannot identify the test path. Verify contained or escaping links, including Windows junctions on Windows, through the host that exercises the behavior. Read and review owner evidence before judging drift. A context-only edit can leave a validation digest unchanged, so compare inspection or content when the claim depends on body changes.

## Native run records

Record the authorized task, candidate digest, source commit, managed integration, host and model settings, limits, and teardown. Keep the exact requests, relevant native command and result traces, trial changes, and safe outcomes. Redact credentials and unrelated content. Missing traces leave the corresponding observation unverified. Verify process termination and temporary-resource cleanup when the run ends.

To check an actual repository-source error on POSIX, use an unprivileged account and a disposable repository. Make one owned declared context file unreadable. Before the model run, verify that the bundled CLI reports an operational source error for that exact path. Observe whether the actor reports the error and unavailable validation without retrying unchanged input, broadening into Fix, or checking a replacement snapshot. Restore the original permissions and verify cleanup. This observation covers the exercised host and does not change the semantic verdict counts.

Keep native observations separate from fixture conformance and published semantic results. Fixture checks establish inputs and grading contracts. Selected recordings establish the reported outcomes for their exact requests, artifact, and host settings.
