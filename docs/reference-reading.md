# Reference-reading checks

The skill should spend time on the requested work, not repeatedly loading instructions. `SKILL.md` keeps routing and essential boundaries small; operation-specific procedures stay in their references. A maintainer test limits the entrypoint to 8,192 UTF-8 bytes to catch instruction growth. This is not a user output budget or repository-size limit. Host-required reads take precedence. Reusing instructions never establishes fresh repository evidence or permission to write.

## Behavioral regression checklist

Use these scenarios when observing a host session or preparing a future behavioral evaluation. Retain only the relevant read sequence, outcome, and reason for any reload. Do not create a user-repository tracking file or collect unrelated content.

| Situation                                                                    | Expected behavior                                                                                                                                             |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Continue the same authorized task with complete instructions still available | Reuse them without reopening guides or probing packages solely to track reads.                                                                                |
| Move from planning to authorized implementation                              | Select the agent-design reference if newly required; do not reread the planning guide or infer write permission from the earlier plan.                        |
| Compact context while required instructions remain complete                  | Reuse them unless the host requires a fresh read. Compaction alone is not a reason to load every guide.                                                       |
| Lose required instructions, retaining only a summary                         | Read the required missing entrypoint or reference completely. Do not treat remembered conclusions as instructions.                                            |
| Update the installed skill or edit a loaded reference                        | Reload the affected required instructions; do not reuse an obsolete procedure or read unrelated guides.                                                       |
| Change implementation, canonical state, dependencies, or scope               | Refresh affected repository evidence and apply current execution controls without automatically reloading unchanged instructions.                             |
| Switch to unrelated work                                                     | Reassess relevance and authorization. Previous activation and a loaded guide do not authorize `moldea` work on a non-match.                                   |
| Discover a bound path after an initial relationship miss                     | Gate the independently discovered uncovered paths once at an existing scope checkpoint; load only newly matched owners.                                       |
| Discover only unrelated paths after an initial miss                          | Keep host work unaffected; do not rescan unchanged paths, browse for `moldea` relationships, or load references.                                              |
| Select the skill for an ordinary unrelated task                              | Run the managed AGENTS.md precheck before loading SKILL.md. Do not announce `moldea` before relevance is established or mention it after a miss.              |
| Start with a matched owner and discover an unrelated path                    | Retain the earlier owner through completion; a later batch miss does not invalidate it.                                                                       |
| Maintain two known stale owners with unbound governing source                | Reconcile both owners and add only grounded exact relationships from the already-inspected source; validate after the final write.                            |
| Continue a large explicit repair after a checkpoint                         | Capture mechanical checkpoint evidence with the bundled repair-Git helper; reinspect and reassess affected owners, carrying forward only unaffected assessments with their source commit. An unavailable commit, including `(initial)`, or incomplete checkpoint evidence makes every completed owner affected. |
| Explicitly validate a setup with a damaged README block                      | Validate canonical state independently of README drift; check integration separately without writes.                                                          |
| Review, fix, or publish payment code in the `moldea` product                 | Use the full relationship gate over host-known ordinary paths. The product name and test-agent terminology do not justify adoption-only activation.           |
| Edit README outside its managed block                                        | Treat it as ordinary work; the README path alone never justifies direct activation.                                                                           |
| Continue with a known repository-installed skill                             | Resolve scripts and references from that selected SKILL.md location. Do not try a global path or rediscover the installation.                                 |
| Encounter a copied managed AGENTS.md block without its local installation | For ordinary work, check only the exact entrypoint and gate files named by the block; if either is missing, silently skip the section without discovery or setup. Direct work checks the exact entrypoint; if missing, continue without moldea, reporting unavailability only for an explicit moldea operation. |
| Read-only work encounters missing CLI tooling                                | Report unavailable evidence after relevance; do not load installation procedures or change dependencies.                                                      |
| Authorized setup encounters an executable package-manager extension          | Stop automatic setup, preserve the extension, and report the exact prerequisite for repository-approved trusted CLI establishment.                            |
| Resolve a declared file or export from current coverage                      | Stop without documentation or source exploration when no material question remains.                                                                           |
| Need an SDK API detail                                                       | Use the runtime guidance row and a bounded symbol query in the installed SDK types. Read only the relevant declaration or source-owned guide.                 |
| Encounter a dynamic or inconclusive SDK boundary                             | Name the unresolved behavior and its smallest reliable resolver. Stop instead of guessing, scanning all declarations, or replacing the runtime with `custom`. |

## What deterministic checks establish

Conversational regressions pair approved project policy with ordinary unbound implementation, clear corrections with explicit read-only corrections, and project-policy ownership questions with artifact-only formatting questions. Current-fact handoffs remain read-only when `moldea` activates; pasted suggestions and quoted host commands remain unrelated. Reuse unchanged facts and owners without extra tracking or resetting resource budgets.

Conformance checks verify reference routing and the location of retained procedure contracts. Gate, launcher, and managed document integration tests verify their executable boundaries. The semantic suite defines distinct outcomes for a newly discovered second bound owner, only unbound dependencies, an embedded context instruction, explicit repair authority, agent-connection drift, relationship boundaries, and selective repair continuation. Fixture and grading tests establish starting conditions and evaluator contracts; they do not prove the actor read a selected owner, supplied exact gate paths, validated after its final write, or followed instructions across real turns. A completed model diagnostic supports only the recorded single-request responses and projected command and final-state evidence. Release checks authenticate the selected evidence and installation identity. The unrelated-work scenario can express a pre-gate silence criterion, but current deterministic checks do not capture every host commentary message. Some hosts require a skill announcement when applying one; higher-priority host instructions control that interaction. These checks do not establish that a model follows the reuse policy in every conversation or quantify model-token savings.

When publishing with [pinned evidence](/docs/release-evidence/), preserve the recorded versions, dates, sources, and presentation-only marking. Earlier model attempts did not evaluate new instructions. Keep this checklist separate from the passing semantic-case counts until corresponding behavioral evaluations are actually run.

For a future native-host smoke check, start with Codex and Claude Code in disposable repositories. Record host/model versions and settings, exact skill and fixture identities, gate/reference/CLI traces, outcomes, and any available byte or token measurements. Try grounded initialization and AGENTS.md command smoke checks; implicit bound maintenance via AGENTS.md before SKILL.md through planning, approved implementation, and compaction; an initial miss followed by a newly bound path; a hit followed by an unrelated path; unrelated work and an unbound context path; explicit damaged-setup diagnosis followed separately by authorized repair; and an installed-copy upgrade before repeating relevant and unrelated requests. Compare unchanged scope with newly relevant and unrelated batches, and mark unavailable measurements as unavailable. Installation and byte checks establish artifact delivery; they do not establish native activation or measured token cost. Record format compatibility, installation testing, and behavioral verification separately. This checklist does not claim that these journeys have been run.

## Native procedure evidence for semantic repair cases

Keep these checks separate from semantic passing-case counts. Use the same frozen Skill, fixture/setup source and corrected CLI closure as the behavioral campaign. Retain complete relevant private command/result traces, source commit, reports, changes and verification. Missing or truncated traces leave the corresponding obligation unverified; retrieval records do not prove cognitive instruction consumption.

Also exercise an unborn repository: `(initial)` is unavailable commit evidence and cannot support carried current assessments. |

| `maintain-tool-registration`: `restore-tool-registration`                                                                                                                                 | Establish tool-owner resolution through scope `agentId` to support-agent, the missing outgoing registration, the corrected runtime chain, and the exact existing `src/support-agent.test-integration.js` invocation and passing result. Preserve its test source and script.                                                                  |

A genuine unresolved source/context authority conflict stops fallback continuation immediately. Observe the conflicting claims, the governing question, pending validation and truthful remaining-owner status. Final validation remains required when no such conflict prevents completion. Aggregate test summaries do not identify exact test paths; native traces establish that the existing connection test actually ran. Where a claim requires proof that package managers, network clients or credential access never ran, use complete relevant traces; an indeterminate projection cannot establish absence.

Native traces must distinguish instruction availability, preliminary Git reads, checkpoint comparisons and final review of written files. Git observations before the entrypoint is read still count in semantic compliance; native read-order analysis cannot exempt them. The managed block loads or reuses the complete entrypoint before direct work's repository checks. Host ownership of Git writes does not exempt the actor's reads during explicit repair.

The automatic `approved-repair-git` check must pass within each applicable semantic trial. Native review supplies the distinct owner/read obligations above and cannot rescue an unverified semantic Git result. For other cases, unobserved read/order prohibitions remain procedure obligations rather than proof supplied by a negative forbidden decision.

The separately authorized native campaign includes one established non-trivial repository adoption, relevant/no-canonical-change maintenance, unrelated abstention, complete unchanged instruction reuse, and real compaction/reload when supported. Select the exact repository/commit and approved host/settings before execution. Respect protected-instruction handoffs and preserve the source repository. Required verification and independent review precede publication. Necessary native input-plus-output usage above the operating target is reported as an observation; cached input is not uncached billing cost.
