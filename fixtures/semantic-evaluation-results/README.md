# Semantic evaluation results

This directory stores protocol 23 semantic evaluation attempts generated by the current runner. Historical attempts remain immutable and may cover an earlier active inventory without representing current completeness. Every terminal recorded run writes one immutable attempt directory containing:

- `attempt.json`: the derived status, cases, confirmations, command-policy and resource aggregates, exact actor and judge provenance, and execution-origin counts when the attempt supports exact stage reuse
- `evidence.json`: the exact schema-7 checkpoint that produced the summary
- `identity.json`: the attempt and evidence digests bound to the clean source commit, relevant-source digest, portable-skill digest, CLI closure, semantic input digest, and invocation arguments

`latest.json` is created with the first attempt and identifies the newest attempt and last passing attempt independently. A newer failure remains visible and cannot be hidden by an older pass.

Current assurance accepts only a complete attempt whose 74-case suite, coverage, portable skill, CLI closure, protocol, and host contract match current source. Exact actor or judge stages may come from verified committed passing evidence when their complete stage identities match; their provenance remains explicit and they are not counted as new executions. Only a complete current 74-case attempt can create `fixtures/semantic-evaluation-result.json` or support a `74/74` public claim.

The public website generates attempt routes and search records only for evidence matching the active evaluation contract. Predecessor-suite files remain internal provenance when exact stage reuse references them, but they do not appear as current or historical public results.

The wrapper keeps an ignored receipt at `fixtures/.semantic-evaluation-identity-receipt.json` only while a recording invocation is unresolved. Run `npm run eval:semantic:identity` to finalize one attributable attempt after an interrupted wrapper. This command does not invoke a model and rejects active processes, multiple or mismatched claims, stale state, and ambiguous evidence.

Run `npm run eval:semantic:verify` to recalculate current evidence digests, summaries, directory identities, pointers, command-policy evidence, and resource budgets without making model calls.
