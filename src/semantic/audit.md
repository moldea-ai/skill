# Skill semantic audit handoff

The audit reviewed all 106 starting case definitions and their 460 criteria against the current Skill, case-owned seeds/overlays, relevant setup helpers and projected evidence contract. The resulting suite has 114 cases and 494 criteria. This is an engineering review handoff, not a runtime catalog or behavioral result. Definitions remain authoritative in `cases/<case-id>/case.ts`. The authoritative suite digest is computed by preflight and pinned in the candidate freeze record.

The eight additions cover unavailable commit evidence, independent missing path/owner lists, bounded partial coverage, relationship materiality, and explicit/conflicting/absent manager guidance. Missing/conflicting manager fixtures require installation by withholding the local CLI; the README-guided healthy installation remains available, so that case grades grounded initialization and validation without requiring manager narration or proving an installation choice. Unavailable-checkpoint fixtures provide no checkpoint ref. The materiality fixture includes the actual locked production CLI closure. Fixture conformance tests materialize every discovered case and check its declared starting paths; focused tests also exercise the material state/connection scenarios. No paid semantic or native campaign has run for this candidate.

## Evidence decisions

Expected outcomes require supported final files, reported comparisons and recognized command results. Forbidden decisions need positive evidence. Negative decisions do not prove absence of unobserved reads, exact inputs, execution order or reassessment. Those obligations remain intact at their native evidence boundary. See `docs/reference-reading.md` for exact continuation labels and native checks; complete unchanged instructions, compaction/reload and adopted-repository behavior need the separately authorized campaign.

`approved-repair-git` and `repair-git-compliance` have mandatory deterministic guards; only the former requires a positive Git observation. Private metadata is required on each captured command, including failed/empty-output commands. Incompatible records are rejected. Unknown execution cannot pass. Static Git forms are classified independently across conditional, pipeline and background lists, without claiming that a branch ran; passive read lists can pass without Git; a retained semantic verdict cannot bypass this result. Raw commands, refs, paths and output bodies are not retained by the projection. Existing evidence selections are preserved as recorded data, without conversion or new assurance.

All five identified seed catch-alls and the additional generated project catch-alls were accidental drift, not the behavior under test. The correction keeps real bindings and exact evidenced project paths, removes unevidenced context-only implementation globs, and preserves deliberate malformed manifests, unresolved requirements, hostile notes, warning causes and moved/broken connections. No fake implementation file was added to justify a relationship. The routing fixture also duplicated its bound implementation and declared a nonexistent test in its dynamic scenario; both were corrected locally.

Connection tests named `.test.mjs` could not produce the category-specific passing-test facts required for meaningful execution evidence. Their source-derived names and scripts now agree with the existing projector. The retirement test still intentionally depends on its removed source and must be removed with the obsolete agent.

The Lantern configuration/lockfile finding still requires its actual owner/source evidence from the responsible project-run session; no case-specific verdict is inferred here. Configuration is not excluded by category. River's missing conversational offer requires no Skill rule. Pre-gate announcements remain covered by existing silence and host-priority rules.

Actor requests now explicitly authorize canonical agent adoption and the governing routing-description decision. Initialization includes a grounded audience where completion is expected. Hypothetical Skill proposals no longer declare nonexistent artifact roots. Abstention allows its silent relevance precheck and host review instructions provide the evaluator's hardened diff form. A policy-conflict repair may start with scope or inspection and must still stop for the developer decision. Structural validation does not require inventory traversal, and a navigation-only project link does not require an implementation relationship. Equivalent boundary questions and concise warning-acceptance reports are accepted without ceremonial wording.

Protocol 30 normalizes supported launcher/gate paths and recognizes built-in Node test reporters and safe stream duplication. Piped test facts require explicit pipefail and a complete passing summary; arbitrary test execution remains unverified for repair Git compliance. Native read history, unchanged-owner reassessment and successful checkpoint capture remain unverified by semantic projection. Low-priority npm test, repair git --version and duplicate host-review observations require no additional machinery: the documented host/test and exact repair command boundaries still govern.
