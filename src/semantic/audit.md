## Evidence decisions

Expected outcomes require supported final files, reported comparisons and recognized command results. Forbidden decisions need positive evidence. Negative decisions do not prove absence of unobserved reads, exact inputs, execution order or reassessment. Those obligations remain intact at their native evidence boundary. See `docs/reference-reading.md` for exact continuation labels and native checks; complete unchanged instructions, compaction/reload and adopted-repository behavior need the separately authorized campaign.

`approved-repair-git` has a mandatory deterministic guard. Private metadata is required on each captured command, including failed/empty-output commands. Incompatible records are rejected. Unknown or conditional execution cannot pass; a retained semantic verdict cannot bypass this result. Raw commands, refs, paths and output bodies are not retained by the projection. Existing evidence selections are preserved as recorded data, without conversion or new assurance.

All five identified seed catch-alls and the additional generated project catch-alls were accidental drift, not the behavior under test. The correction keeps real bindings and exact evidenced project paths, removes unevidenced context-only implementation globs, and preserves deliberate malformed manifests, unresolved requirements, hostile notes, warning causes and moved/broken connections. No fake implementation file was added to justify a relationship. The routing fixture also duplicated its bound implementation and declared a nonexistent test in its dynamic scenario; both were corrected locally.

Connection tests named `.test.mjs` could not produce the category-specific passing-test facts required for meaningful execution evidence. Their source-derived names and scripts now agree with the existing projector. The retirement test still intentionally depends on its removed source and must be removed with the obsolete agent.

The Lantern configuration/lockfile finding still requires its actual owner/source evidence from the responsible project-run session; no case-specific verdict is inferred here. Configuration is not excluded by category. River's missing conversational offer requires no Skill rule. Pre-gate announcements remain covered by existing silence and host-priority rules.
